# STATUS.md 규칙

`STATUS.md`는 **세션이 끊겨도 PM이 정확히 이어서 일할 수 있게 하는 유일한 기억**이다. 세션 시작 훅이 이 파일의 요약을 자동으로 보여준다.

## 원칙
1. **현재 상태만 쓴다**: 끝난 마일스톤의 태스크 표는 `docs/history.md`로 옮기고 STATUS에는 한 줄 요약만 남긴다. 150줄을 넘기지 않는다.
2. **상태가 바뀔 때마다 즉시 갱신한다**: 에이전트에게 일을 맡기기 전과 결과를 받은 직후에 갱신한다. 나중에 몰아서 쓰지 않는다.
3. **"다음 할 일"은 그대로 실행할 수 있게 쓴다**: 새 세션의 PM이 이 줄만 보고 바로 다음 에이전트를 부를 수 있어야 한다.
4. PM만 수정한다.

## 양식

```markdown
# STATUS: <프로젝트명>

- 현재 단계: 요청 접수 | 명세 | 설계 | M1 구현 | M1 통합 검증 | 최종 검수 | 완료 | 보류
- 규모: 소 | 중 | 대 (근거: 한 줄)
- 마지막 갱신: YYYY-MM-DD HH:MM

## 마일스톤
| ID | 이름 | 상태 | 포함 AC |
|---|---|---|---|
| M1 | … | 진행 | AC-1 ~ AC-4 |
| M2 | … | 대기 | AC-5 ~ AC-9 |

## 태스크 (현재 마일스톤)
| ID | 내용 | 상태 | 반려 횟수 | 최근 문서 |
|---|---|---|---|---|
| T-01 | 환경 구성 | 완료 | 0 | docs/reviews/T-01-r1.md |
| T-02 | … | 리뷰 반려 | 1 | docs/reviews/T-02-r1.md |
| T-03 | … | 대기 | 0 | - |

태스크 상태: 대기 → 구현 → 리뷰 → (리뷰 반려 → 구현) → 완료. QA는 마일스톤 끝에 한 번(`docs/qa/M<n>-int-rN.md`), 실패하면 수정 태스크를 만든다.

## 사용자 결정 대기
- (없음) | 무엇을 물었는지, 어느 문서에 있는지

## 열린 이슈
- (없음) | 설계 문제, 3회 반려 등

## 다음 할 일
- developer에게 T-02 수정 요청 (근거: docs/reviews/T-02-r1.md)
```

## 세션 재개 절차
1. 세션 시작 훅이 보여준 STATUS 요약을 읽는다. 여러 프로젝트가 진행 중이면 사용자에게 어느 것을 이어갈지 묻는다.
2. 해당 프로젝트의 `STATUS.md` 전체와 "최근 문서"를 읽는다.
3. **프로젝트 폴더에서 `git status`로 STATUS와 실제 상태가 맞는지 확인한다.** 예: STATUS는 "구현"인데 커밋되지 않은 변경이 있다면 developer가 도중에 끊긴 것이다 → 같은 태스크를 다시 맡기며 "이어서 마무리"라고 알린다.
4. "사용자 결정 대기"가 있으면 먼저 사용자에게 묻는다.
5. "다음 할 일"부터 이어간다.

## 중단 복구 (세션이 작업 도중 꺼졌을 때)
세션 시작 훅이 "이전 세션이 아래 에이전트 작업 도중 꺼졌습니다"와 프로젝트의 "커밋되지 않은 변경"을 보여 준다.
기본 원칙: **커밋된 것 = 검수를 통과한 것, 커밋되지 않은 것 = 검수 전**. 커밋된 상태는 믿고, 그 이후만 다시 한다.

| 끊긴 작업 | 처리 |
|---|---|
| architect 설계 | 남은 설계 문서가 있으면 경로를 알려 주며 "이전 시도가 중단됨. 남은 문서를 확인하고 이어서 완성"으로 다시 맡긴다. 없으면 처음부터 |
| developer 구현 | 같은 태스크를 다시 맡기며 "이전 시도가 중단됨. `git status`의 변경 파일을 확인하고 이어서 마무리"라고 알린다. 남은 변경을 지우지 않는다 |
| reviewer 리뷰 / qa 검증 | 같은 회차로 처음부터 다시 맡긴다 (덜 쓴 문서는 덮어씀). 반려 횟수는 늘리지 않는다 |
| security-reviewer | 같은 회차로 처음부터 다시 맡긴다 |

- 중단은 반려가 아니다. 반려 횟수와 재작업 한도에 넣지 않는다.
- STATUS의 단계·태스크 상태가 훅이 보여 준 상황과 다르면 실제 파일과 `git status`를 기준으로 STATUS를 먼저 고친다.
- 사용자에게 따로 묻지 않고 바로 다시 맡긴다. 복구한 사실은 다음 보고에 한 줄로 알린다.
