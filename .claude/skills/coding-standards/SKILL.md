# 코딩 규칙 (Python)

- [자동]: 린터(ruff)와 훅이 기계적으로 검사한다. 위반하면 저장 직후 피드백이 온다.
- [판단]: reviewer가 읽고 판단한다.

## 1. 스타일
- [자동] ruff 포맷과 린트를 통과한다. 줄 길이는 100자 이하.
- [자동] 이름: 함수·변수는 `snake_case`, 클래스는 `PascalCase`, 상수는 `UPPER_SNAKE_CASE`.
- [자동] 사용하지 않는 import와 변수를 남기지 않는다.
- [판단] 이름만 보고 역할을 알 수 있게 짓는다. `data`, `tmp`, `x` 같은 모호한 이름 대신 `user_list`, `retry_count`처럼 쓴다.

## 2. 구조
- [자동] 파일 하나는 300줄 이하. 넘으면 모듈을 나눈다.
- [판단] 함수는 한 가지 일만 한다. 40줄을 넘으면 나눌 수 있는지 검토한다.
- [판단] 공개 함수에는 타입 힌트와 한 줄 이상의 docstring을 쓴다.
- [판단] 전역 변수로 상태를 공유하지 않는다. 필요한 값은 함수 인자로 넘긴다.
- [판단] 같은 코드가 세 번 반복되면 함수로 뺀다.

## 3. 오류 처리
- [자동] `except:`나 `except Exception:`으로 뭉뚱그려 잡지 않는다. 구체적인 예외 타입을 쓴다.
- [판단] 예외를 잡았으면 처리하거나, 로그를 남기고 다시 던진다. 조용히 삼키지 않는다.
- [판단] 사용자 입력은 받는 즉시 검증하고, 잘못되면 이유가 담긴 메시지로 알린다.

## 4. 로깅과 디버깅
- [자동] `src/`에서는 `print` 대신 `logging.getLogger(__name__)`을 쓴다. (단, 사용자에게 보여줄 출력만 담당하는 `cli.py`는 예외)
- [자동] `breakpoint()`, `pdb.set_trace()`를 남기지 않는다.
- [자동] TODO는 `# TODO(T-03): 내용`처럼 태스크 ID를 붙여서만 쓴다.

## 5. 보안
- [자동] 비밀번호, API 키, 토큰을 코드에 직접 쓰지 않는다. 환경변수(`os.environ`)로 읽는다.
- [자동] `eval`, `exec`, `subprocess(..., shell=True)`를 쓰지 않는다.
- [판단] 파일 경로나 명령어에 외부 입력을 그대로 넣지 않는다.

## 6. 금지된 꼼수
검사를 통과하려고 아래 행동을 하면 안 된다. 반드시 해야 한다면 이유를 PM에게 보고한다.
- 검사를 끄는 주석(`# noqa`, `# type: ignore`)이나 설정 변경
- 실패하는 테스트를 삭제, `skip` 처리, 또는 기대값을 틀린 쪽에 맞춰 수정
- 설계 문서에 없는 기능을 임의로 추가
