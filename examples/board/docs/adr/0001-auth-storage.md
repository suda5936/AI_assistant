# 0001. 인증 데이터 저장 방식 (비밀번호 해시, 세션, 아이디 정규화)

- 상태: 승인 (대표 승인, 대행 기록 2026-10-03)
- 날짜: 2026-10-03
- 관련: 회사 표준 `/docs/adr/0001-standard-stack.md`, 명세 Q1·Q2·Q3·Q11, AC-2·AC-5·AC-8·AC-9·AC-10

## 맥락
표준 스택은 "서버 세션 + HttpOnly 쿠키, 해시는 hashlib.scrypt 또는 argon2"까지만 정한다. 세션을 어디에 어떤 형태로 둘지, 해시 파라미터와 저장 형식, 아이디를 어떤 형태로 저장할지는 데이터가 쌓이면 되돌리기 어렵다. 그래서 여기에 기록한다.

## 결정
1. **비밀번호 해시**: 표준 라이브러리 `hashlib.scrypt`(n=16384, r=8, p=1, dklen=64)를 쓴다. 솔트는 사용자마다 16바이트 무작위 값이다. 저장 형식은 `scrypt$16384$8$1$<salt_b64>$<hash_b64>`이고 파라미터를 함께 저장하므로 나중에 강도를 올릴 수 있다. 외부 라이브러리를 쓰지 않는다.
2. **세션 저장**: SQLite `sessions` 테이블에 둔다. 쿠키 값은 `secrets.token_urlsafe(32)` 토큰이고, DB에는 토큰의 SHA-256 해시만 저장한다(DB가 유출돼도 세션을 탈취할 수 없음). 로그인 시점부터 7일 고정 만료(Q3)이며 연장하지 않는다. 로그아웃하면 행을 물리 삭제하므로 이전 쿠키는 바로 무효가 된다(AC-9).
3. **쿠키 속성**: `board_session`, `HttpOnly; SameSite=Lax; Path=/; Max-Age=604800`. `Secure`는 `SESSION_COOKIE_SECURE` 설정으로 켠다(Q11).
4. **아이디 정규화**: 입력은 `[A-Za-z0-9_]{4,20}`을 허용하고 소문자로 바꿔 저장한다. 로그인도 소문자로 바꿔 조회한다. 그래서 `Alice`와 `alice`는 같은 아이디다(Q1). 중복은 `users.username` UNIQUE 제약으로 막는다.

## 대안과 기각 이유
- **argon2 (argon2-cffi)**: 더 현대적이지만 외부 의존성(C 확장)이 추가된다. 사내 소수 인원 규모에서는 scrypt로 충분하다.
- **서명 쿠키(무상태 세션)**: DB 조회가 없지만 로그아웃 시 서버에서 즉시 무효화할 수 없어 AC-9를 만족하기 어렵다.
- **세션 토큰 원문 저장**: 구현이 조금 단순하지만 DB 유출이 곧 세션 탈취가 된다.
- **대문자 입력을 형식 오류로 거부**: 규칙은 단순하지만, 로그인할 때 대문자를 섞어 입력한 사용자가 실패 원인을 알기 어렵다.

## 결과
- 의존성이 추가되지 않는다. 해시 계산(약 16MB 메모리, 수십 ms)으로 가입·로그인 응답이 조금 느려진다.
- 만료된 세션 행은 조회될 때만 지워진다. 정기 청소는 하지 않는다(소규모라 허용).
- 무차별 대입 제한은 하지 않는다(Q9). 한계로 보고한다.
