## 목적
팀원이 회원가입 후 공지·잡담 글을 올리고, 누구나 읽을 수 있는 작은 웹 게시판을 만든다.

## 범위
- 포함: 회원가입, 로그인/로그아웃(새로고침 후 유지), 게시글 목록(페이지네이션)·상세, 글쓰기, 본인 글 수정·삭제, 화면 문구는 한국어
- 제외: 댓글, 첨부파일, 검색, 관리자 기능, 회원 탈퇴, 비밀번호 변경·찾기, 이메일 인증, 소셜 로그인, 추천/조회수, 마크다운·서식 편집

## 마일스톤
| ID | 이름 | 포함 AC |
|---|---|---|
| M1 | 회원가입·로그인 | AC-1 ~ AC-10 |
| M2 | 게시글 | AC-11 ~ AC-25 |

## 완료 기준

### M1 회원가입·로그인
- AC-1: 유효한 아이디와 비밀번호로 가입하면 계정이 생성되고 성공 응답을 받는다.
- AC-2: 이미 존재하는 아이디로 가입하면 "이미 사용 중인 아이디" 오류가 나고 계정이 추가되지 않는다. (대소문자 구분 여부: Q1)
- AC-3: 비밀번호가 최소 길이 미만이면 가입이 거부되고 사유가 표시된다. (제안: 8자 미만 거부, 8자는 허용)
- AC-4: 아이디가 비어 있거나 공백뿐이거나 허용 형식을 벗어나면 가입이 거부되고 사유가 표시된다. (제안: 영문 소문자·숫자·밑줄, 4~20자)
- AC-5: 가입 후 DB를 조회하면 비밀번호가 평문이 아니라 솔트가 적용된 해시로 저장돼 있다.
- AC-6: 올바른 아이디·비밀번호로 로그인하면 로그인 상태가 되고 화면 상단에 내 아이디가 표시된다.
- AC-7: 틀린 비밀번호 또는 존재하지 않는 아이디로 로그인하면, 두 경우 모두 동일한 오류 메시지가 나오고 로그인되지 않는다.
- AC-8: 로그인한 상태에서 브라우저를 새로고침해도 로그인 상태와 아이디 표시가 유지된다.
- AC-9: 로그아웃하면 화면이 비로그인 상태가 되고, 로그아웃 전의 세션 쿠키로 보낸 요청은 인증되지 않는다.
- AC-10: 세션 쿠키는 HttpOnly이다. 응답 어디에도 비밀번호 또는 해시가 포함되지 않는다.

### M2 게시글
- AC-11: 게시글이 하나도 없을 때 목록 화면은 "게시글이 없습니다"를 표시한다.
- AC-12: 로그인하지 않은 사용자도 목록을 볼 수 있고, 글은 작성 시각이 최신인 순서로 페이지당 N개씩 표시된다. (N 제안: 10, Q4)
- AC-13: 글이 N+1개 있으면 1페이지에 N개, 2페이지에 1개가 표시되고 페이지 이동 UI가 있다. 글이 N개 이하면 페이지 이동 UI는 없다.
- AC-14: 존재하지 않는 페이지 번호(0, 음수, 숫자 아님, 마지막 페이지 초과)를 요청하면 정해진 방식으로 처리한다. (Q4)
- AC-15: 로그인하지 않은 사용자도 상세 화면에서 제목, 내용, 작성자 아이디, 작성 시각을 볼 수 있다. (시각 형식: Q6)
- AC-16: 존재하지 않는(또는 삭제된) 글 ID의 상세를 요청하면 "게시글을 찾을 수 없습니다" 안내가 나온다. API는 404.
- AC-17: 로그인하지 않은 사용자에게는 글쓰기 진입이 로그인 안내로 대체되고, 글 작성 API 요청은 401로 거부되며 글이 생기지 않는다.
- AC-18: 로그인한 사용자가 제목과 내용을 입력해 저장하면 글이 생성되고 작성자는 본인이며, 상세 화면으로 이동한다.
- AC-19: 제목 또는 내용이 비어 있거나 공백뿐이면 저장이 거부되고 사유가 표시되며 글이 생기지 않는다.
- AC-20: 제목 또는 내용이 최대 길이를 넘으면 저장이 거부된다. 최대 길이 이하(경계값)는 저장된다. (제안: 제목 100자, 내용 5000자, Q5)
- AC-21: 작성자가 자기 글을 수정해 저장하면 변경 내용이 상세 화면과 목록에 반영된다. 제목·내용 검증은 AC-19, AC-20과 동일하다.
- AC-22: 작성자가 자기 글을 삭제하면 목록에서 사라지고 상세 요청은 404가 된다. (삭제 전 확인 창: Q7)
- AC-23: 남의 글 상세와 목록에는 수정·삭제 버튼이 보이지 않는다. 비로그인 사용자에게도 보이지 않는다.
- AC-24: 로그인한 사용자가 남의 글에 대해 수정·삭제 API를 직접 호출하면 403으로 거부되고 글은 변하지 않는다. 비로그인이면 401이다.
- AC-25: 제목·내용에 `<script>alert(1)</script>` 같은 HTML을 넣어 저장해도 화면에서 스크립트가 실행되지 않고 입력한 글자 그대로 텍스트로 표시된다.

## 제약 조건
- 기술 스택은 `docs/adr/0001-standard-stack.md` 표준(FastAPI + SQLite + React/TypeScript)을 따른다. (루트의 `docs/adr/`)
- 비밀번호는 해시로 저장하고, 로그인 상태는 HttpOnly 쿠키 세션으로 유지한다.
- 브라우저(데스크톱)에서 사용한다. 모바일 최적화는 요구하지 않는다.

## 확정된 결정 (Q1~Q11, 모두 PM 제안대로 확정)
- Q1 (아이디 규칙): 허용 형식을 영문 소문자·숫자·밑줄 4~20자로 제안한다. 대소문자는 구분하지 않고 소문자만 허용하는 방식(Alice와 alice는 같은 아이디 취급)으로 제안한다. 괜찮은가? (답변: 제안대로 확정)
- Q2 (비밀번호 규칙): 최소 8자, 최대 72자(해시 방식 제한 고려), 문자 조합 제한은 없음으로 제안한다. 괜찮은가? (답변: 제안대로 확정)
- Q3 (로그인 유지 기간): 새로고침 유지는 필수다. 브라우저를 닫았다 다시 열어도 유지되어야 하는가, 유지 기간은? 제안: 7일, 이후 자동 로그아웃. (답변: 제안대로 확정)
- Q4 (페이지네이션): 페이지당 10개, `?page=N` 방식으로 제안한다. 범위 밖 페이지는 어떻게 할까? 제안: 숫자가 아니거나 1 미만이면 1페이지로 보정, 마지막 페이지 초과는 빈 목록 대신 마지막 페이지로 보정. (답변: 제안대로 확정)
- Q5 (글 길이/형식): 제목 최대 100자, 내용 최대 5000자, 내용은 평문(줄바꿈만 유지, 마크다운 미지원)으로 제안한다. 괜찮은가? (답변: 제안대로 확정)
- Q6 (시간 표시): 작성 시각을 한국 시간(KST) `YYYY-MM-DD HH:mm`으로 표시하는 것으로 제안한다. 수정한 글에 "수정됨/수정 시각" 표시가 필요한가? 제안: 불필요. (답변: 제안대로 확정)
- Q7 (삭제 방식): 삭제 전 확인 창을 띄우고, 삭제는 복구 불가(완전 삭제)로 제안한다. 괜찮은가? (답변: 제안대로 확정)
- Q8 (가입 직후): 가입 성공 후 자동 로그인할까, 로그인 화면으로 보낼까? 제안: 로그인 화면으로 이동. (답변: 제안대로 확정)
- Q9 (로그인 보호): 로그인 실패를 반복하는 무차별 대입 공격에 대한 제한(예: 같은 아이디 5회 실패 시 5분 잠금)이 필요한가? "기본적인 보안" 범위에 넣을지 여부. 제안: 이번에는 제외하고 한계로 보고. (답변: 제안대로 확정)
- Q10 (작성자 표시와 삭제된 작성자): 작성자는 아이디로 표시한다. 회원 탈퇴가 없으므로 별도 처리는 없다. 맞는가? (답변: 제안대로 확정)
- Q11 (운영 환경): 사내 소수 인원용으로 SQLite 단일 서버, HTTPS 종단은 사내 인프라 몫으로 두고(쿠키 Secure 속성은 설정으로 제공) 진행해도 되는가? (답변: 제안대로 확정)

## 세부 보강 (설계 중 발견, 승인된 범위 안의 엣지 케이스)
