## DELETE 문서의 422에 대한 판단: 허용 가능한 한계
- 사실 확인: FastAPI 0.142.2에서 `responses`에 422를 넣지 않은 DELETE 라우트(경로 인자 하나)를 따로 만들어 보니, 응답 목록이 `['204', '422']`로 나왔다. 라우트에 인자가 있으면 FastAPI가 422(`HTTPValidationError`)를 자동으로 넣고, 이 동작은 `responses`로 빼는 방법이 없다. 422를 직접 선언하는 방법으로만 덮어쓸 수 있다
- 실제로 일어나지 않는다는 점도 확인: DELETE의 인자는 `post_id: str`(posts.py:71)와 `get_current_user`(deps.py:33-47, 쿠키를 `Request`에서 직접 읽음)뿐이라 Pydantic 검증 단계에서 실패할 곳이 없다
- 허용하는 이유
  1. 문서에 나온 형식(`ErrorResponse`)은 이 API의 모든 오류 형식과 같아서, 문서를 보고 만든 클라이언트가 잘못 동작할 일이 없다. r1에서 문제 삼은 "형식 불일치"는 사라졌고, 남은 것은 "나올 수 없는 코드 하나가 더 적혀 있음"뿐이다
  2. 이것까지 없애려면 `app.openapi`를 바꿔 만들어진 문서를 후처리하는 코드가 필요한데, 이는 설계에 없는 기능이고 이득에 비해 유지 비용이 크다. `"4XX"`나 `"default"` 키로 자동 추가를 피하는 방법은 오히려 문서를 더 모호하게 만든다
  3. 코드 주석(posts.py:23)에 이유가 적혀 있어 나중에 읽는 사람이 실수로 오해하지 않는다
- 남길 일: 02_design.md "API 계약"의 DELETE 오류 목록(401, 404, 403, 411, 413, 415)과 생성된 OpenAPI 문서가 422 하나만큼 다르다. 판정에는 반영하지 않고 아래 #1 Minor로 기록한다
