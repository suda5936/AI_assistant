## 요청받은 확인 항목에 대한 판단
- **미들웨어 순서**: `main.py:27-29`의 등록 순서가 M2.md:76-81과 같다. `test_non_json_with_large_body_is_415_first`, `test_non_json_chunked_is_415_first`가 415가 411·413보다 먼저 나오는 것을 검증한다. 문제 없음.
- **Content-Length 거짓 값**: 실제보다 작게 적으면 h11이 적힌 길이만큼만 읽으므로 우회되지 않는다(위 표). 크게 적으면 413이다. 숫자가 아닌 값은 h11이 먼저 400으로 거절하고, 앱 단독으로도 411이다. 남은 우회 경로는 #1 하나다.
- **CSP 값**: API 응답은 JSON뿐이므로 `default-src 'none'; frame-ancestors 'none'`이 적절하다. CSP는 그 응답을 문서로 열 때만 적용되므로 프론트 페이지의 `fetch`에는 영향이 없다. 프론트 HTML의 CSP는 02_design.md:343에서 운영 프록시가 붙이도록 따로 정해 두었다. 이것은 이 태스크 범위가 아니다.
- **/docs 끄기와 openapi 내보내기**: `/docs`, `/redoc`, `/openapi.json`은 404다(실제 서버에서도 확인). `openapi_export.py`는 `create_app().openapi()`를 직접 부르므로 영향이 없고, `test_openapi_export_still_works`가 이를 검증한다.
- **기존 테스트 2개의 `app.openapi()` 전환**: `/openapi.json` 라우트는 `app.openapi()`의 결과를 그대로 돌려줄 뿐이다. 따라서 응답 코드 선언(401·415·422 등)을 검증하는 힘은 같다. 빠진 것은 HTTP로 문서를 내보내는 경로뿐이고, 그 경로는 이제 404가 계약이며 `test_documentation_paths_are_404`가 검증한다. 검증력은 유지된다.
