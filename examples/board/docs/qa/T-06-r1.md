# T-06 QA 1회차

대상 AC 없음. 기준은 docs/02_design.md "실행 방법". 구현 코드는 읽지 않았고 명령 실행 결과만 확인했다.

## 실행 결과
| 항목 | 명령 | 결과 |
|---|---|---|
| 프론트 lint / format:check / typecheck | `npm run lint`, `format:check`, `typecheck` (frontend) | 모두 exit 0 |
| 프론트 test | `npm run test` | 1 파일 1 테스트 통과 |
| 프론트 coverage | `npm run coverage` | 통과, App.tsx 100% (임계값 70% 충족) |
| 루트 check | `make check` | exit 0 (백엔드 + 프론트) |
| 루트 coverage | `make coverage` | exit 0 |
| 루트 audit | `make audit` | exit 0, pip-audit 취약점 없음, npm audit는 moderate 5건만(기준 high 이상이라 통과) |
| `make dev` | 백엔드 8000, 프론트 5173 동시 기동 | 둘 다 기동, `GET :5173/` 200 |
| /api 프록시 | `curl :5173/api/auth/me` | 401, `{"error":{"code":"unauthenticated","message":"로그인이 필요합니다."}}` (JSON, 백엔드 직접 호출 :8000도 동일 401) |
| `make e2e-backend` + `e2e-frontend` | 8001 / 5174 기동 | `:8001/api/auth/me` 401, `:5174/api/auth/me` 401 JSON(프록시가 8001로 연결됨), `tests/e2e/e2e.db` 생성 확인 |
| `make -n e2e` | 드라이런 | `cd tests/e2e && npm ci && npx playwright test` (설계와 일치) |

확인 후 기동한 서버는 모두 종료했다.

## 발견 사항
| # | 등급 | 위치 | 문제 | 수정 지시 | 담당 |
|---|---|---|---|---|---|
| 1 | Minor | Makefile `e2e-backend` | `tests/e2e/` 디렉터리가 없으면 `unable to open database file`로 실패한다. 현재 저장소에 해당 디렉터리가 없어 처음 실행 시 실제로 재현됐다. `make e2e`로 실행할 때는 `cd tests/e2e`가 먼저 필요하고 QA가 이 디렉터리를 만들므로 정상 흐름에서는 문제가 되지 않는다. | `e2e-backend`에 `mkdir -p $(CURDIR)/tests/e2e`를 추가하면 단독 실행도 안전하다(선택). | developer |

## 환경 한계
- Playwright 시나리오(tests/e2e)는 아직 작성 전(M1 통합 검증 때 작성)이라 `make e2e` 전체는 실행하지 않았다. 서버 기동 구조(e2e-backend, e2e-frontend, 포트, DB 초기화, 프록시)만 수동 확인했다.
- 브라우저는 `/opt/pw-browsers`에 chromium-1194가 있다. 이번 태스크는 브라우저 실행이 필요 없어 판정에 영향 없다.
- `tests/e2e/`는 확인을 위해 임시로 만들었다가 삭제했다(e2e.db 포함).
