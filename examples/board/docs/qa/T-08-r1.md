# T-08 QA 1회차

범위: AC-1, AC-2, AC-3, AC-4, AC-6, AC-7의 화면 부분(가입·로그인 화면). 헤더 관련(시나리오 1, 6의 헤더 아이디 표시, 8)은 T-09 범위라 제외. 구현 코드는 읽지 않았고 M1.md의 SignupPage·LoginPage 절과 통합 검증 시나리오 2~5를 기준으로 작성했다.

## 실행 결과
- 명령: `cd tests/e2e && npm install && npx playwright test` (Playwright가 `make e2e-backend`(8001)와 `make e2e-frontend`(5174)를 직접 띄움, chromium)
- 결과: 6개 통과, 0개 실패 (10.9초)
- 첫 화면 기동 확인: `/`, `/signup`, `/login`이 모두 크래시 없이 뜨고 제목(게시판/회원가입/로그인)이 보이며, pageerror·console error가 없다.

## 발견 사항
없음 (Critical/Major/Minor 모두 0건).

참고(결함 아님)
- 첫 실행에서 BOOT 테스트가 실패했으나 테스트의 오류였다. 비로그인 `/api/auth/me`의 401은 설계된 정상 응답인데, 브라우저가 이를 console error("Failed to load resource ... 401")로 남기고, 내 단언이 이를 잡았다. 그 로그 한 종류만 제외하도록 수정했다. pageerror와 그 밖의 console error는 여전히 실패로 판정한다.
- 이번 범위에서는 쿠키 `httpOnly=true`, `document.cookie`에 `board_session` 없음(AC-10)도 로그인 시나리오 안에서 같이 확인되어 통과했다.
- 로그인 성공 후 헤더의 아이디 표시(AC-6 후반)와 새로고침 유지(AC-8)는 T-09 이후 M1 통합 검증에서 확인한다.
